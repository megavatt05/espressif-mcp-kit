# HMI Layout Budget, Collision & Overflow Control

Навык регламентирует стандарты проектирования, математического контроля заполнения пространства, предотвращения наложений (коллизий) и исключения выходов за пределы дисплея (Screen Overflow) для промышленных панелей оператора (HMI), станков, медицинских и измерительных приборов на базе **LVGL 8/9**, **Qt**, **Slint**, **TouchGFX** и **Embedded Web**.

---

## 1. Когда активировать данный навык

- Разработка экранов HMI для станков (ЧПУ, намоточные, упаковочные), приборов и терминалов.
- Жалобы оператора/пользователя: «компоненты не помещаются», «кнопка срезана снизу/справа», «кнопки слишком мелкие для пальца», «много пустого места на экране», «текст наезжает друг на друга».
- Перед прошивкой или сборкой прошивки для верификации геометрии (Automated Layout Verification).
- При миграции проекта на **LVGL 9** (проверка сброса скрытых паддингов темы).
- При локализации интерфейса на русский или немецкий язык (проверка удлинения строк).

---

## 2. Ключевые метрики и правила верстки HMI

### 2.1. Принцип абсолютного отсутствия вертикального скролла на главном экране
> [!IMPORTANT]
> На главном экране управления промышленного оборудования **вертикальный скролл запрещен**.
> Все ключевые индикаторы (телеметрия, уставки, прогресс) и кнопки оператора (ПУСК, ПАУЗА, СТОП, СБРОС) должны быть видны одновременно в фиксированном Viewport ($W \times H$).

### 2.2. Бюджет заполнения пространства (Screen Fill Factor $k_{fill}$)
$$k_{fill} = \frac{\sum S_{\text{блоков}}}{W_{\text{viewport}} \times H_{\text{viewport}}} \times 100\%$$

- **< 55% (Underutilized / Пустыня):** Разрозненные элементы, избыточный воздух, рассеивание внимания оператора.
- **65% – 82% (Industrial Sweet Spot):** **Золотой промышленный стандарт.** Гармоничный вес, достаточные безопасные зазоры, высокая читаемость.
- **> 85% (Overcrowded / Перегруз):** Слишком плотная компоновка, риск ложных срабатываний тачскрина, когнитивная усталость.

### 2.3. Стандарт сенсорных кнопок под палец (Touch Target Standard)
- **Минимум по W3C WCAG 2.5.5 / ISO 9241-410:** не менее **44 × 44 px** (при ~170 DPI / шаг точки ~0.15 мм).
- **Рекомендуемый промышленный размер для подушечки пальца:** **60 × 60 px** или **ширина от 74 px** для прямоугольных клавиш.
- **Кнопка аварийного СТОП или ключевые действия:** от **80 px**.
- **Зазор безопасности (Safety Gap):** между любыми соседними интерактивными кнопками должен быть зазор **не менее 8 px** (рекомендуется **10–14 px**).

### 2.4. Безопасная граница экрана (Safety Margin)
- Элементы интерфейса не должны прилегать к физическому краю матрицы вплотную (0 px), так как механическая рамка корпуса или безель дисплея срезает крайние пиксели.
- Оставлять отступ безопасности по периметру: **от 4 до 8 px**.

## 3. Подводный камень: Скрытые паддинги тем в LVGL 9 (Theme Padding Trap)

В **LVGL 9** виджет `lv_tabview` по умолчанию через дефолтную тему (`lv_theme_default`) применяет внутренние отступы:
- на контейнер содержимого (`lv_tabview_get_content()`);
- на саму страницу вкладки (`tab_main`).

Это скрытно срезает **~32–40 px по высоте** и **~24–32 px по ширине**. В результате нижняя строка кнопок (например, на $Y=464$ при высоте 550) срезается физическим краем экрана, а правые блоки вылезают за границу!

### Обязательный рецепт сброса паддингов в LVGL 9:
```c
// 1. Создаем tabview
lv_obj_t *tabview = lv_tabview_create(lv_screen_active());
lv_tabview_set_tab_bar_size(tabview, 50); // Высота шапки вкладок

// 2. СБРАСЫВАЕМ скрытые паддинги контейнера контента
lv_obj_t *content = lv_tabview_get_content(tabview);
lv_obj_set_style_pad_all(content, 0, 0);
lv_obj_set_style_pad_gap(content, 0, 0);

// 3. Создаем вкладку и СБРАСЫВАЕМ паддинги самой страницы
lv_obj_t *tab_main = lv_tabview_add_tab(tabview, "Главный");
lv_obj_set_style_pad_all(tab_main, 0, 0);
lv_obj_set_style_pad_gap(tab_main, 0, 0);
lv_obj_remove_flag(tab_main, LV_OBJ_FLAG_SCROLLABLE); // Отключаем случайный скролл
```

## 4. Автоматизированная проверка геометрии (CLI & скрипты)

В состав навыка входит автономный валидатор геометрии [`scripts/verify_hmi_layout.py`](scripts/verify_hmi_layout.py):

### Запуск верификации:
```bash
# Проверка спецификации экрана из JSON файла
python scripts/verify_hmi_layout.py my_screen_spec.json

# Проверка с генерацией интерактивного HTML-отчета
python scripts/verify_hmi_layout.py my_screen_spec.json --html layout_report.html

# Запуск со встроенной эталонной спецификацией
python scripts/verify_hmi_layout.py
```

### Формат спецификации экрана (JSON):
```json
{
  "screen": {
    "name": "Намоточный станок ПОН",
    "width": 1024,
    "height": 550,
    "safe_margin": 6
  },
  "elements": [
    {"name": "card_meter", "x": 10, "y": 8, "width": 520, "height": 264, "interactive": false},
    {"name": "card_preset", "x": 536, "y": 8, "width": 478, "height": 130, "interactive": false},
    {"name": "btn_start", "x": 10, "y": 464, "width": 190, "height": 74, "interactive": true},
    {"name": "btn_stop", "x": 366, "y": 464, "width": 150, "height": 74, "interactive": true}
  ]
}
```

### Что проверяет валидатор:
1. **Screen Clipping:** выход любого элемента за границы $0, 0, W, H$.
2. **AABB Collisions:** взаимное пересечение элементов одного уровня.
3. **Touch Ergonomics:** размер интерактивных кнопок меньше 44 px.
4. **Safety Gaps:** опасная близость или отсутствие зазоров между кнопками.
5. **Space Budget:** расчет коэффициента заполнения $k_{fill}$ и классификация по эргономическим зонам.

## 5. Чек-лист проверки перед передачей в производство

- [ ] **Viewport Check:** Все элементы умещаются в пределах видимой области (без вертикального скролла).
- [ ] **Bottom Button Clearance:** От нижнего края нижних кнопок до края рабочей зоны есть запас не менее 6–10 px.
- [ ] **Touch Target Size:** Все сенсорные кнопки имеют ширину и высоту не менее 44 px (рекомендуется от 60 px).
- [ ] **Inter-Button Gap:** Расстояние между соседними кнопками составляет не менее 8 px.
- [ ] **Screen Fill Factor:** Коэффициент заполнения полезной площади экрана находится в диапазоне 65% – 82%.
- [ ] **Text Overflow Defense:** Для надписей с переменной длиной (или при локализации на русский язык) установлен режим `LV_LABEL_LONG_DOTS` или моноширинная маска чисел.
- [ ] **No Hidden Theme Pads:** В коде явно обнулены паддинги родительских контейнеров `lv_obj_set_style_pad_all(obj, 0, 0)`.
